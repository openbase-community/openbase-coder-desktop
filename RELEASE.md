# Desktop Release

Pushing `main` or `staging` runs `.github/workflows/electron-rebuild.yml`.
That workflow is the sole publisher: it builds the renderer and Swift
screen-share companion, signs and notarizes the app and DMG, and uploads the
release artifacts to S3. If publishing fails, fix or rerun the workflow; do
not publish from a developer workstation.

The workflow and its invoked scripts own the release procedure. This document
records the artifact and DMG contracts that those implementations must
preserve.

The S3 publisher uploads, per architecture:

- Versioned immutable artifacts: `mac/Openbase-<version>-<arch>.dmg`,
  `.zip`, and `.zip.blockmap`
- Stable latest aliases: `mac/Openbase-latest-<arch>.<ext>` for the same
  files. Publishing also refreshes `Openbase-Coder-latest-*` transition
  aliases until existing landing and Cloud download links have moved.
- The electron-updater feed metadata: `mac/latest-mac.yml`

The DMG is the human download; electron-updater on macOS installs from the
zip (plus blockmap for differential downloads) referenced by `latest-mac.yml`.
The feed URL baked into the app comes from `build.publish` in `package.json`
(see the workspace `AUTO_UPDATE.md`).

The current Apple Silicon latest URL is:

```text
https://openbase-coder-desktop-releases-632795836081-us-east-1.s3.amazonaws.com/mac/Openbase-latest-arm64.dmg
```

## DMG layout

`scripts/build-dmg.mjs` produces a styled drag-to-install DMG: the app on the
left, an Applications shortcut on the right, a large drag arrow on a branded
Retina background ("Drag Openbase to Applications"), a fixed 660x400
window with hidden toolbar/status bar, and a custom volume icon. The
background is rendered at build time from `assets/dmg/background.html` (the
single source of truth for the design) by `scripts/generate-dmg-background.mjs`
using the devDependency Electron, then combined into a HiDPI TIFF with
`tiffutil`. The icon layout is written into the volume's `.DS_Store` by
scripting Finder over a mounted read-write image before converting to
compressed read-only ULFO.

Keep the icon anchor coordinates in `build-dmg.mjs` and the arrow/text
placement in `assets/dmg/background.html` in sync (both note the shared
geometry).

First launch from `/Applications` offers to eject the mounted DMG and trash
the downloaded installer, enumerating the exact volumes and files in the
dialog (see `electron/installer-cleanup.cjs`); a packaged first launch from
anywhere else (`~/Applications`, the mounted DMG) instead offers to move the
app to `/Applications` — the only supported install location — and relaunch.
Each prompt is remembered per installation in the app's userData directory.
Automated installs (E2E, release verification) can suppress both prompts with
`OPENBASE_DESKTOP_DISABLE_INSTALLER_CLEANUP=1`.

CI supplies signing and notarization credentials through GitHub Actions
secrets. Keep the workflow environment aligned with
`scripts/check-mac-release-prereqs.mjs`; never add credentials or generated
release artifacts to git.

Ordering note: `latest-mac.yml` is generated by electron-builder before
`notarize-dmg.mjs` re-signs and staples the DMG, so the DMG entry's sha512 in
the feed is stale. That is fine: the macOS updater only downloads the zip
entry, which notarization does not touch. Do not add any step that modifies
the zip after electron-builder emits it, or the updater checksum will break.
The app-level signing identity must stay the same Developer ID across
releases or electron-updater will reject downloaded updates.
